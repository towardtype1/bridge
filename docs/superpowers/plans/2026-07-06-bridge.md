# Bridge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Star Trek bridge themed multi-agent orchestration harness in Rust: a Captain agent decomposes missions into concurrent workstreams executed by station agents in isolated git worktrees, driven by the local Claude Code CLI in headless mode, guarded by a hook-based mid-run veto system, observed through a native egui GUI.

**Architecture:** A cargo workspace of nine crates. `bridge-core` holds all shared types and is the interface contract; every other crate depends on it. Version-fragile CLI surfaces (flags, NDJSON schemas, hook payloads) are isolated in `bridge-compat`. A tokio engine spawns `claude -p` child processes; an axum control server adjudicates every tool call via a fail-closed hook helper binary; an eframe GUI observes everything through a broadcast event bus and answers escalations through a command channel.

**Tech Stack:** Rust 2024 edition, tokio, axum, serde/serde_json, toml, rusqlite (bundled), eframe/egui, ureq (helper only), regex, thiserror, tracing, proptest (dev).

## Global Constraints

- Never call the Anthropic API directly. Every agent turn spawns the locally installed `claude` CLI in headless mode inside the workstream's worktree.
- Remove `ANTHROPIC_API_KEY` and Claude-session env vars (`CLAUDECODE`, `CLAUDE_CODE_SESSION_ID`, `CLAUDE_CODE_ENTRYPOINT`, `CLAUDE_CODE_CHILD_SESSION`) from every child process environment.
- Never pass `--bare` (it skips OAuth/keychain and breaks subscription auth).
- All parsers must be schema-tolerant: unknown fields ignored, unknown event types logged and skipped, never a panic.
- All version-fragile logic (flag construction, payload field access) lives only in `bridge-compat`.
- Hook gating fails CLOSED: control server unreachable or timed out means deny (PreToolUse).
- Merges to main always require explicit user confirmation in the GUI. Pushing to a remote is a separate escalated action, never automatic.
- Concurrent `claude` processes capped by a semaphore, configurable, default 3.
- Branch naming: `bridge/<mission-slug>/<workstream-slug>`.
- Default max Kobayashi Maru rounds: 3.
- No em dashes in any file; plain `-` only.
- TDD throughout: failing test first, then implementation, then green run.

## Verified Ground Truth (captured 2026-07-06, claude CLI 2.1.201, macOS)

Live fixtures captured in `crates/bridge-compat/tests/fixtures/`. Findings that lock design decisions:

1. **stream-json event types observed:** `system/init`, `system/thinking_tokens`, `assistant`, `user`, `result/success`, `rate_limit_event`. Docs additionally define `system/api_retry` (fields: `attempt`, `max_retries`, `retry_delay_ms`, `error_status`, `error` with categories incl. `rate_limit`, `overloaded`, `billing_error`) and `stream_event` (partial messages, only with `--include-partial-messages`).
2. **`result` event fields:** `subtype` ("success" observed; error subtypes exist), `is_error`, `api_error_status`, `duration_ms`, `duration_api_ms`, `num_turns`, `result` (final text), `stop_reason`, `session_id`, `total_cost_usd`, `usage`, `modelUsage`, `permission_denials[]`, `terminal_reason` ("completed"), `uuid`.
3. **`rate_limit_event`:** `rate_limit_info: { status: "allowed" | ..., resetsAt: unix_ts, rateLimitType, overageStatus, overageResetsAt, isUsingOverage, overageInUse }`. Non-"allowed" status plus `resetsAt` drives the pause + retry-at countdown.
4. **`system/init` fields:** `session_id`, `tools[]` (use to validate station allowlists at preflight), `model`, `permissionMode`, `claude_code_version`, `apiKeySource` ("none" = subscription auth confirmed working from scrubbed env).
5. **Hook payloads (real 2.1.201):** common fields `session_id`, `transcript_path`, `cwd`, `prompt_id`, `permission_mode`, `hook_event_name`. PreToolUse adds `tool_name`, `tool_input`, `tool_use_id`. PostToolUse adds `tool_response`, `duration_ms`. Stop adds `stop_hook_active`, `last_assistant_message`, `background_tasks`, `session_crons`.
6. **Hook response schema (current):** `{"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "allow"|"deny"|"ask"|"defer", "permissionDecisionReason": "..."}}`. Exit 0 + stdout JSON is the decision path. Exit 2 = blocking error. Plain `{}` = no opinion, normal permission flow continues.
7. **Policy-pass responses use `{}` (passthrough), not `allow`:** an explicit `allow` bypasses the remaining permission system including the static `--allowedTools` gate. Passthrough keeps both gates active. `allow` is reserved for user-approved escalations.
8. **Native HTTP hooks (`"type": "http"`) fail OPEN** on connection failure ("non-blocking error, execution continues"). This is why the helper binary exists: a command hook that cannot reach the control server prints a deny decision itself. Do not use HTTP hooks for gating.
9. **Project `.claude/settings.json` hooks DO fire in `-p` mode** with `--setting-sources project`. Engineering installs settings by writing that file into each worktree and passing `--setting-sources project,local` scoped flags.
10. **`--resume <session-id>` keeps the SAME session_id** and retains conversation context. `num_turns` counts only the new turns. Resume lookup is scoped to the directory (and its worktrees), so always resume from the same worktree cwd.
11. **Flag spellings (2.1.201):** `--allowedTools`/`--allowed-tools` (both), `--disallowedTools`/`--disallowed-tools`, `--max-turns`, `--output-format stream-json`, `--verbose`, `--resume <id>`, `--model`, `--settings <file-or-json>`, `--setting-sources user,project,local`, `--json-schema <schema>`, `--permission-mode`, `--fallback-model`, `--session-id <uuid>`, `--tools <list>`, `--include-partial-messages`, `--strict-mcp-config`, `--mcp-config`.
12. **`--bare` warning confirmed** in help text: "OAuth and keychain are never read". Docs say bare may become the DEFAULT for `-p` in a future release: the compat module must detect this (result: `apiKeySource` / auth errors) and the tested-version ceiling guards it.
13. **Structured output:** `--output-format json --json-schema '<schema>'` returns validated JSON in a `structured_output` field. Used for Captain plan graphs and Kobayashi BattleReports.
14. **Tested version range for config default:** min `2.1.190`, max `2.2.x` (2.1.196+ guarantees `prompt_id`; 2.1.201 is the capture version).

## Risks

- CLI drift: mitigated by compat isolation + tested-version range + fixtures pinned to 2.1.201.
- `--bare`-by-default future: preflight asserts `apiKeySource` != api key when subscription expected; version ceiling warns first.
- Hook `ask` in headless mode: NOT used; escalation is held open at the control server instead (helper waits, hook timeout 600s, server answers before helper deadline).
- egui version churn: pin exact versions in workspace manifest.
- Subscription quota burn during tests: all engine tests use the fake CLI; only Phase C smoke uses real claude on haiku.
